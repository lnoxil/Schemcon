# План исследования и реализации бесплатного конвертера Minecraft-схем

## 1. Что такое «конвертер схем» в контексте Minecraft
Конвертер схем — это утилита, которая:
- читает файл схемы (обычно `.schem` или `.schematic`) из одной версии игры;
- сопоставляет блоки/состояния блоков (BlockStates), их теги и свойства с целевой версией;
- автоматически заменяет блоки, отсутствующие в старой версии, на наиболее похожие аналоги;
- пересобирает итоговую схему, совместимую с более старой версией.

Цель: переносить постройки между версиями (например, 1.21 → 1.16/1.12/1.8) с сохранением формы, цвета и функциональности в пределах доступных блоков.

## 2. Требования, которые нужно покрыть
1) Поддержка нескольких форматов схем (минимум `.schem`, опционально `.schematic`).
2) Автоматическая замена блоков по принципам:
   - полублоки → полублоки,
   - ступеньки → ступеньки,
   - цветы → цветы,
   - блоки с похожим цветом и формой → наиболее близкие аналоги,
   - при отсутствии блока в версии — корректная деградация (fallback).
3) Группировка блоков по категориям (типы и подтипы).
4) Система правил замены и приоритетов.
5) Сравнение разных версий (источник/цель) на уровне ID, тегов, имён, свойств BlockState.

## 3. Архитектура решения (пошагово)
### Шаг 1. Исследование форматов схем
- Определить формат входного файла (`.schem` или `.schematic`).
- Понять структуру: палитра блоков, NBT-данные, BlockStates, свойства (например, `facing`, `half`, `waterlogged`).
- Задача: унифицировать извлечение списка блоков со свойствами, координатами и NBT.

### Шаг 2. Сбор базы блоков и свойств по версиям
- Сформировать реестр блоков для каждой версии Minecraft (например, 1.21, 1.20.6, 1.19.4, 1.18.2, 1.16.5, 1.12.2, 1.8.9).
- Для каждого блока собрать:
  - ID/имя (`minecraft:oak_planks`),
  - свойства BlockState (например, `axis`, `facing`, `half`, `shape`, `waterlogged`),
  - теги/категории (например, `stairs`, `slabs`, `flowers`, `wool`, `glass`).
- Источник данных: официальные registry JSON, wiki, данные клиентских jar, или API из проектов (например, registries из Mojang mappings).

### Шаг 3. Нормализация и группировка блоков
- Ввести категории (пример):
  - structural: planks, stone, bricks
  - slabs, stairs
  - glass, stained_glass
  - wool, terracotta
  - flowers, crops, plants
  - redstone
  - special (entities, tile-entities, heads, banners)
- Каждому блоку назначить:
  - группу,
  - цветовую категорию (по палитре или HSV-среднему),
  - форму (full, slab, stair, fence, wall, etc.).

### Шаг 4. Построение правил замены
- Правила замены задаются в таблице:
  - ключ: блок + свойства
  - значение: целевой блок + свойства
- Правила должны учитывать:
  - идентичные блоки (оставляем как есть),
  - прямые аналоги (например, `oak_slab` → `wood_slab`),
  - редкие блоки (цветы, кораллы, резные блоки) → ближайшие аналоги категории.

### Шаг 5. Алгоритм выбора «самого похожего» блока
- При отсутствии прямого аналога:
  1. Оставить категорию (stairs/slab/flower).
  2. Сопоставить цвет (RGB/HSV).
  3. Сопоставить форму (full/half/fence/wall).
  4. Сопоставить материал (stone/wood/etc).
- Это обеспечит замену «максимально похожих» блоков.

### Шаг 6. Применение конверсии
- Пройтись по всем блокам схемы.
- Для каждого блока:
  - найти точное совпадение в целевой версии,
  - иначе применить правила замены,
  - иначе применить «похожий по цвету/форме/группе».
- Итог: сформировать новую палитру блоков и BlockStates.

### Шаг 7. Проверка результата
- Проверить, что итоговый `.schem` открывается в целевой версии.
- Проверить, что блоки не ломают геометрию.
- Отдельно проверить сущности (tile entities, banners, heads).

## 4. Минимальный MVP
1. Конвертация `.schem` (Litematica).
2. Таблица замен для 1.21 → 1.16.
3. Сохранение результата в `.schem`.
4. Консольный инструмент (CLI) с параметрами:
   ```
   convert --input build.schem --from 1.21 --to 1.16 --output build_1.16.schem
   ```

## 5. Дополнительные идеи
- Поддержка `.schematic` (WorldEdit).
- GUI/веб-интерфейс.
- Режим отчетов: статистика замен.
- Режим «строгий» (не заменять, если нет точного аналога).
