# Schemcon

Бесплатный конвертер Minecraft-схем (`.schem`) между версиями. Инструмент строит mapping блоков между версиями и заменяет палитру схемы.

## Что уже есть
- Загрузка реестров блоков для выбранной версии.
- Если в server.jar нет `reports/blocks.json`, включается цепочка fallback: блоки из server tags, затем из client jar (`assets/minecraft/blockstates`), и только потом внешний источник (PrismarineJS). Это сильно снижает вероятность падения `fetch-registry`.
- Автоматическое построение mapping по форме, семейству и цвету блока.
- Конвертация `.schem` через замену палитры.
- Поддержка палитры как в стандартных `.schem` (Sponge `Palette`), так и в Litematic-подобных схемах (`Regions/*/BlockStatePalette`).

## CLI
### 1) Скачать реестры
```bash
python -m schemcon fetch-registry 1.21
python -m schemcon fetch-registry 1.16.5
```

### 2) Построить mapping
```bash
python -m schemcon build-mapping \
  --source-dir data/versions/1.21 \
  --target-dir data/versions/1.16.5 \
  --output data/mappings/1.21-to-1.16.5.json
```

### 3) Конвертировать схему
```bash
python -m schemcon convert \
  --input input.schem \
  --output output_1.16.5.schem \
  --mapping data/mappings/1.21-to-1.16.5.json \
  --report conversion_report.json
```

## GUI (автоматический режим)
Запуск:

```bash
python -m schemcon gui
```

В GUI теперь достаточно указать:
- исходную версию,
- целевую версию,
- входной `.schem`,
- выходной `.schem`.
- (Опционально) папку сервера `plugins/FastAsyncWorldEdit/schematics` и имя файла для FAWE-импорта.

После нажатия кнопки запускается полный конвейер автоматически:
1. скачивание/подготовка реестров,
2. построение mapping,
3. конвертация схемы,
4. вывод лога и таблицы замен **только тех блоков, которые реально были в палитре схемы**.

В таблице есть:
- исходный блок,
- блок-замена,
- причина выбора,
- свойства обоих блоков (`shape`, `family`, `color`).

При выборе строки показываются визуальные мини-превью: сначала реальная текстура блока из `client.jar` (если доступна), иначе цветовая карточка как fallback.

Если указать папку FAWE, программа автоматически копирует итоговый `.schem` в `plugins/FastAsyncWorldEdit/schematics` и в лог выводит готовую команду вида `//schem load <имя>`.
Для FAWE при копировании в папку `schematics` выполняется приведение к Sponge-совместимому формату (если исходник был region/litematic-подобным), чтобы `//schem load` видел файл. При записи файл принудительно сохраняется в gzip-формате `.schem`, чтобы избежать раздувания размера. Дополнительно нормализуются `Name/Properties` blockstate-записей и выставляется корректный `DataVersion` (fallback 1.16.5), чтобы снизить риск NPE в FAWE при загрузке.
Также автоматически создается fallback-вариант `_v3.schem` для загрузчиков, которым нужен Sponge v3 (основной файл — v2).


## Ограничения
- Для очень разреженных region-схем при FAWE-экспорте применяется перепаковка областей, чтобы не раздувать итоговый размер файла.
- Конвертация меняет палитру без пересчета BlockData для обычного Sponge-формата; для region/litematic-подобных схем при FAWE-экспорте палитра нормализуется с очисткой несовместимых Properties у заменённых блоков.
- При коллизиях палитры используется безопасный fallback-блок, чтобы не оставлять «пустые» ordinals для FAWE.

## Почему размер `original.schem` и `converted.schem` может отличаться
- Это нормально: после конвертации меняются строки в `Palette`, пересобирается `BlockData` и может измениться степень gzip-сжатия.
- Даже при одинаковой геометрии/количестве блоков размер файла может быть больше или меньше.
- В `report.json` теперь добавляется секция `file_sizes` (`input_bytes`, `output_bytes`, `delta_bytes`, `ratio`, `*_is_gzipped`) для прозрачной диагностики размера.
